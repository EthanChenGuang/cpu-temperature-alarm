## Tech Debt Detail

### Cross-cutting: Windows Production Validation

The project's core value — *reliable audible and WhatsApp warning before hardware damage* — depends on Windows-only subsystems (LHM/pythonnet, winsound, pystray, PyInstaller, Task Scheduler). All phases defer live verification to a Windows target machine per D-15/D-08 conventions. This is intentional for WSL development but represents **12 pending human verification items** before production confidence.

**Recommended Windows smoke test (single session):**

1. `pwsh scripts/fetch-lhm.ps1`
2. Copy `config/config.example.json` → `config/config.json`; add CallMeBot credentials
3. `python -m src.main` — confirm tray icon, sensor menu, settings persist
4. Trigger threshold (or lower threshold temporarily) — confirm beep + WhatsApp
5. `pwsh scripts/build.ps1` — confirm exe launches
6. `pwsh scripts/install-autostart.ps1` (admin) — reboot test

### Minor: Orphan API

`read_sensors()` in Phase 1 was designed as the Phase 2 consumption API (D-12). Phase 2/3/4 use `TelemetryPoller.run_once()` instead. Consider removing the export or documenting it as a convenience API — no functional impact.
